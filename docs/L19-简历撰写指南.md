# L19 - 简历撰写指南

> **"简历不是你做了什么的流水账，而是你能创造什么价值的证据。"**

---

## 📌 本节目标

1. 掌握 STAR 法则在简历中的应用
2. 学会四个详略等级的简历描述
3. 建立量化数据对照表
4. 对比普通写法 vs 优化写法
5. 了解不同岗位方向的调整策略

---

## 一、STAR 法则在简历中的应用

| 要素 | 英文 | 简历体现 | 示例 |
|------|------|---------|------|
| **S** | Situation | 一句话背景 | 推荐系统承载亿级用户… |
| **T** | Task | 融入标题 | 从零构建 For You 推荐管道 |
| **A** | Action | 每个 bullet | 实现了 Grok-based Transformer 排序模型… |
| **R** | Result | 量化收尾 | 19 维行为预测，端到端延迟 <250ms |

## 二、简历描述（4个详略等级）

### 精简版（1行）
```
X For You Feed Algorithm - 基于 Grok Transformer 的亿级推荐系统
```

### 标准版（2-3行）
```
X For You Feed Algorithm                              2024.xx - 2025.xx
• 设计并实现 Grok-based Transformer 推荐排序系统，
  预测 19 种用户行为概率，端到端延迟 <250ms
• 基于 Candidate Pipeline 框架实现 10 级过滤 + 4 级评分管道
```

### 详细版（4-5行）
```
X For You Feed Algorithm                              2024.xx - 2025.xx
技术栈：Rust / Python / JAX / gRPC / Kafka
• 架构：设计 Home Mixer 编排层，协调双路召回（In-Network + Out-of-Network）
• 模型：基于 Grok-1 适配推荐场景，实现 Candidate Isolation 注意力掩码，
  保证评分独立性和可缓存性
• 检索：实现双塔模型 + ANN 向量检索，从 10 亿候选中毫秒级召回 Top-1000
• 性能：bfloat16 混合精度推理，P99 延迟 <500ms
```

### 完整版（6-8行）
```
X For You Feed Algorithm                              2024.xx - 2025.xx
技术栈：Rust / Python / JAX-Haiku / gRPC / Kafka / DashMap
• 架构设计：主导 Candidate Pipeline 通用框架，支持 Source/Filter/Scorer 等
  6 大 Trait 的可组合管道，100% 组件可热插拔
• 排序模型：将 Grok-1 Transformer 适配为推荐排序模型，实现 GQA + RoPE +
  Candidate Isolation，19 维行为预测（含正/负面行为）
• 检索系统：设计 Two-Tower 检索模型 + L2 归一化 + Dot Product 相似度，
  配合 ANN 索引实现亿级帖子毫秒级检索
• 实时存储：用 Rust 实现 Thunder 内存帖子引擎，基于 DashMap 并发读写 +
  Kafka 实时消费，亚毫秒级 In-Network 候选获取
• 评分链路：PhoenixScorer → WeightedScorer → AuthorDiversity → OON，
  负面行为权重 -74x 确保安全内容优先
• 性能优化：bfloat16 推理降低延迟 40%+，Semaphore 背压控制，Zstd 压缩节省 70% 带宽
```

## 三、量化数据对照表

| 维度 | 量化示例 |
|------|---------|
| 规模 | 处理 X 平台 5 亿活跃用户的 For You 推荐 |
| 候选量 | 从 10 亿帖子中检索并排序 |
| 行为维度 | 预测 19 种用户行为概率 |
| 架构组件 | 4 大模块、10 级过滤器、4 级评分器 |
| 延迟 | 端到端 P50 <200ms, P99 <500ms |
| 压缩率 | Zstd 压缩节省 70% 带宽 |
| 内存优化 | Hash 嵌入将 512GB 缩减至 3GB |

## 四、普通写法 vs 优化写法

| 普通描述 ❌ | 优化描述 ✅ |
|------------|-----------|
| 实现了推荐系统 | 设计 Grok-based Transformer 排序模型，19 维行为预测，P99 <500ms |
| 写了过滤逻辑 | 实现 10 级候选过滤管道，380→45 条精准筛选，过滤率 88% |
| 用了 Rust | 基于 DashMap 实现亚毫秒级并发帖子存储，支撑百万 QPS |
| 优化了模型 | bfloat16 混合精度推理，延迟降低 40%，内存减少 50% |
| 做了向量检索 | 双塔模型 + ANN 索引，亿级候选毫秒级 Top-1000 召回 |
| 处理消息队列 | Kafka 实时消费 + TTL 裁剪，7 天窗口内帖子零延迟可查 |

## 五、不同岗位方向调整

### 方向1: ML/推荐算法工程师
重点突出：Transformer 模型设计、多行为预测、Candidate Isolation、双塔检索、训练优化

### 方向2: 后端/系统工程师
重点突出：Rust 并发设计、gRPC 微服务、Kafka 消费、DashMap、管道框架

### 方向3: 基础架构工程师
重点突出：部署架构、监控体系、A/B 测试、热加载、性能优化

### 方向4: 全栈/应用工程师
重点突出：端到端系统设计、四大模块协同、API 设计、数据流
