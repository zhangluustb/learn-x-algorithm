## 正文讲解

### 1. 什么是推荐系统——从"信息过载"说起

想象你走进一个拥有 10 亿本书的图书馆。没有目录、没有分类、没有馆员——你怎么找到自己想读的书？

> **类比**：推荐系统就是那个了解你阅读偏好的"智能馆员"。它不需要你说出具体要什么，而是根据你过去的行为（借了什么书、看了多久、给了什么评价）来预测你下一本想读的书。

在技术上，推荐系统要解决的核心问题是：

$$\text{从海量候选集合 } C \text{ 中，为用户 } u \text{ 选出 top-K 最相关的物品}$$

这个过程通常分三步：

| 阶段 | 任务 | 规模 |
|------|------|------|
| **召回 (Retrieval)** | 从全量候选中快速筛选出可能相关的子集 | 10亿 → 数千 |
| **排序 (Ranking)** | 对召回结果精细打分 | 数千 → 数百 |
| **重排 (Re-ranking)** | 多样性、去重、业务规则调整 | 数百 → 最终展示 |

### 2. 三大推荐范式——协同过滤 vs 内容过滤 vs 深度学习

#### 2.1 协同过滤（Collaborative Filtering）

"和你口味相似的人喜欢什么，你大概率也会喜欢。"

- **核心假设**：相似用户有相似偏好
- **优点**：不需要理解内容本身
- **缺点**：冷启动问题（新用户/新物品没有行为数据）

#### 2.2 内容过滤（Content-Based Filtering）

"你喜欢科幻小说，那这本新出的科幻小说你可能也会喜欢。"

- **核心假设**：用户偏好可以从物品特征推断
- **优点**：没有冷启动问题
- **缺点**：推荐同质化，难以发现惊喜

#### 2.3 深度学习推荐（x-algorithm 所用）

"让神经网络直接从你的行为序列中学习你的偏好。"

- **核心思路**：用 Transformer 编码用户的历史行为序列，预测对新内容的参与概率
- **优势**：自动学习特征，无需手工特征工程
- **x-algorithm 的选择**：完全消除手工特征，让 Grok-based Transformer 做所有"重活"

### 3. X (Twitter) For You 信息流——两条路汇聚为一

当你打开 X 的 "For You" 标签，你看到的内容来自两条路径：

```
┌─────────────────┐     ┌──────────────────────┐
│   In-Network    │     │   Out-of-Network     │
│   (你关注的人)   │     │   (算法发现的内容)    │
│                 │     │                      │
│   Thunder 服务   │     │   Phoenix 检索模型    │
│   亚毫秒级查询   │     │   双塔向量检索        │
└────────┬────────┘     └──────────┬───────────┘
         │                         │
         └─────────┬───────────────┘
                   ▼
         ┌──────────────────┐
         │  Phoenix 排序模型  │
         │  Grok Transformer │
         │  预测 19 种行为    │
         └────────┬─────────┘
                  ▼
         ┌──────────────────┐
         │   加权评分 + 过滤  │
         │   多样性 + 安全    │
         └────────┬─────────┘
                  ▼
           📱 你的信息流
```

**In-Network (Thunder)**：来自你关注的账号的近期帖子。Thunder 是一个基于 Rust 的内存存储引擎，通过 Kafka 实时摄取帖子，提供亚毫秒级查询。

**Out-of-Network (Phoenix Retrieval)**：你没关注，但可能感兴趣的内容。Phoenix 的双塔模型将用户和帖子编码为向量，通过点积相似度检索最相关的帖子。

两条路径的候选合并后，由 Phoenix 排序模型统一打分——它预测你对每条帖子做出 19 种不同行为（点赞、回复、转发、点击…）的概率，然后加权得出最终分数。

### 4. x-algorithm 项目架构全景图

整个系统由四大模块组成：

| 模块 | 语言 | 职责 |
|------|------|------|
| **Home Mixer** | Rust | 编排层，组装整个 For You 管道 |
| **Candidate Pipeline** | Rust | 通用管道框架（Source/Filter/Scorer/Selector） |
| **Thunder** | Rust | In-Network 实时帖子存储与查询 |
| **Phoenix** | Python (JAX) | ML 模型：检索(双塔) + 排序(Transformer) |

```
Home Mixer（大脑）
├── 调用 Thunder 获取关注用户的帖子
├── 调用 Phoenix Retrieval 获取推荐帖子
├── 合并候选 → 数据补全 → 过滤 → 评分 → 选择
└── 返回排好序的信息流
```

**关键设计决策：**

1. **零手工特征**：不像传统系统需要大量特征工程，x-algorithm 让 Transformer 自动学习
2. **候选隔离**：排序时候选帖子之间互不"看见"，确保评分一致性
3. **多行为预测**：不是预测单一"相关度"，而是预测 19 种具体行为的概率

## 💡 本节小结

| 概念 | 一句话总结 |
|------|-----------|
| 推荐系统 | 从海量候选中为用户选出最相关内容的系统 |
| 召回→排序→重排 | 推荐系统的标准三阶段流水线 |
| 协同过滤 | 利用相似用户的行为进行推荐 |
| For You 信息流 | In-Network + Out-of-Network 双路召回，Transformer 统一排序 |
| x-algorithm | 四大模块：Home Mixer / Candidate Pipeline / Thunder / Phoenix |
