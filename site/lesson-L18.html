L18 - 部署架构与监控

"上线不是终点，而是另一段旅程的起点——监控决定了你能否在问题变成事故之前发现它。"

📌 本节目标

  1. 了解微服务部署拓扑
  2. 掌握关键监控指标
  3. 理解 A/B 测试与灰度发布
  4. 认识模型更新与热加载策略

正文讲解

1. 微服务部署拓扑

                        Load Balancer
                             │
                    ┌────────┼────────┐
                    ▼        ▼        ▼
              Home Mixer  Home Mixer  Home Mixer  (N 个实例)
                    │        │        │
          ┌────────┴────────┴────────┘
          │                 │
    ┌─────┴──────┐    ┌────┴─────┐
    │  Thunder   │    │  Phoenix  │
    │  集群 (M)  │    │  GPU集群  │
    └──────┬─────┘    └──────────┘
           │
    ┌──────┴─────┐
    │   Kafka    │
    │   集群     │
    └────────────┘
服务 资源类型 扩缩策略
Home Mixer CPU 按 QPS 水平扩缩
Thunder 高内存 CPU 按数据量垂直扩缩
Phoenix GPU (TPU) 按推理延迟自动扩缩
Kafka 存储 + 网络 按消息吞吐量扩分区

2. 关键监控指标

延迟指标

指标 P50 目标 P99 目标 告警阈值
E2E 总延迟 <200ms <500ms P99 >800ms
Phoenix 推理 <80ms <200ms P99 >300ms
Thunder 查询 <5ms <20ms P99 >50ms
过滤耗时 <10ms <30ms P99 >50ms

质量指标

指标 含义 健康范围
候选数/请求 Source 返回的候选总数 200-500
过滤率 被 Filter 去除的比例 30-50%
OON 比例 最终结果中 Out-of-Network 占比 40-60%
作者多样性 不同作者数/结果数 >0.7
新鲜度 最新帖子的年龄 <2小时

Thunder 专有指标

FOUND_FRESHNESS_SECONDS     → 最新帖子的年龄
FOUND_TIME_RANGE_SECONDS    → 帖子时间跨度
FOUND_UNIQUE_AUTHORS        → 独立作者数
FOUND_REPLY_RATIO           → 回复占比

3. A/B 测试

用户请求 → 分桶器（用户ID hash）
              │
    ┌─────────┼──────────┐
    │ 桶A(50%) │ 桶B(50%) │
    ▼          ▼          
  Pipeline_V1  Pipeline_V2
  (当前权重)    (新权重)
    │          │
    ▼          ▼
  指标收集    指标收集
    │          │
    └────┬─────┘
         ▼
   统计显著性检验
   (P值 < 0.05？)

常见实验维度： - WeightedScorer 权重调整 - 新增/移除 Filter - 模型版本对比 - 候选数量变化

4. 模型更新策略

                    训练集群              在线集群
                ┌──────────────┐    ┌──────────────┐
新数据 ───────► │ 训练新模型    │    │ 当前模型 V1  │ ◄── 在线请求
                │ 验证指标      │    │              │
                │ 导出参数      │    │              │
                └──────┬───────┘    └──────────────┘
                       │                    │
                       ▼                    │
                ┌──────────────┐            │
                │ 参数存储      │            │
                │ (S3/GCS)     │────────────┘
                └──────────────┘    热加载新参数
                                    (无需重启服务)

热加载流程： 1. 新模型训练完成，参数上传到对象存储 2. Phoenix 服务定期检查参数版本 3. 发现新版本 → 加载参数到内存 4. 原子切换：旧参数 → 新参数 5. 监控指标，异常则自动回滚

💡 本节小结

主题 要点
部署拓扑 Home Mixer(CPU) + Thunder(内存) + Phoenix(GPU)
关键指标 延迟 P99 <500ms，OON 比例 40-60%
A/B 测试 用户分桶，统计显著性检验
模型更新 热加载参数，无需重启，支持回滚
