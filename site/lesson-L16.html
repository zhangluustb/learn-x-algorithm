正文讲解

1. 零手工特征工程的设计哲学

传统推荐系统需要大量手工特征：

传统方案：
├── 用户特征：年龄、性别、地区、活跃度...
├── 帖子特征：文本TF-IDF、话题标签、媒体类型...
├── 交叉特征：用户-话题偏好、用户-作者亲密度...
└── 上下文特征：时间、设备、网络类型...

x-algorithm 方案：
└── 用户行为序列 → Transformer → 自动学习一切

为什么这样设计？

维度 手工特征 自动学习
开发成本 需要大量领域专家 端到端训练
数据管道 复杂的 ETL 流程 只需行为日志
特征漂移 需要持续监控更新 模型自动适应
新信号接入 需要设计新特征 增加行为类型即可
上限 受人类认知限制 可捕获非直觉模式

核心洞察：Transformer 足够强大，可以从原始行为序列中自动发现传统需要手工设计的所有模式——甚至更多。

代价： - 模型体量更大，推理延迟更高 - 需要更多训练数据 - 可解释性降低（黑盒预测）

2. Candidate Isolation 的可缓存性

回顾 L08 的核心创新——候选帖子之间看不到彼此。

没有 Candidate Isolation 时的问题：

批次 A: [帖子1, 帖子2, 帖子3] → 帖子1 得分 = 0.85
批次 B: [帖子1, 帖子4, 帖子5] → 帖子1 得分 = 0.72  ← 分数变了！

帖子1 的分数取决于同批次的其他帖子——这意味着每次换批次都要重新计算，无法缓存。

有 Candidate Isolation 时：

批次 A: [帖子1, 帖子2, 帖子3] → 帖子1 得分 = 0.85
批次 B: [帖子1, 帖子4, 帖子5] → 帖子1 得分 = 0.85  ← 分数相同！

可缓存性带来的工程价值：

  1. 减少计算：已评分的帖子不需要重复推理
  2. 增量更新：新帖子只需计算自己的分数
  3. 跨请求复用：同一用户的多次请求可以共享分数
  4. 并行化：候选可以独立评分，无需协调

3. Hash-Based Embeddings 的工程优势

$$\text{传统嵌入表大小} = \text{实体数} \times \text{维度}$$

X 有约 5 亿活跃用户、数十亿帖子。如果每个实体一个嵌入：

方案 嵌入表大小 (256维, float32)
全量 ID 嵌入 5亿 × 256 × 4 = 512 GB
Hash 嵌入 (100万桶) 100万 × 256 × 4 = 1 GB
Multi-Hash (3个) 3 × 1 GB = 3 GB

Hash 冲突的缓解：

多哈希策略让冲突的影响显著降低。假设每个哈希函数的桶数为 $M$，两个不同实体在单个哈希函数上冲突的概率为 $1/M$，在 $k$ 个哈希函数上全部冲突的概率为：

$$P(\text{全部冲突}) = \left(\frac{1}{M}\right)^k$$

当 $M=10^6, k=3$ 时，$P = 10^{-18}$，实质上不可能。

4. 多行为预测 vs 单一相关性分数

方案 输出 灵活性 可解释性
单一分数 1 个"相关度" 低——改目标需重训模型 低——不知道为什么推荐
多行为预测 19 个概率 高——改权重即可调风格 高——知道预测了什么行为

实际应用场景：

目标：减少争议性内容
方案：调高 block/mute/report 的负权重
    weights.report = -100  (原 -74)
效果：预测"可能被举报"的内容被更强力压制

目标：增加视频内容
方案：调高 video_view 的正权重
    weights.vqv = 1.0  (原 0.01)
效果：有视频且被预测会观看的帖子排名上升

关键：不需要重新训练模型，只需调权重。 这大大缩短了产品迭代周期。

5. 可组合管道架构的扩展性

x-algorithm 的 Candidate Pipeline 框架让增删组件变得极其简单：

// 新增一个 Source：加入广告候选
pipeline.source(Box::new(AdCandidateSource::new()));

// 新增一个 Filter：过滤低质量内容
pipeline.filter(Box::new(QualityFilter::new()));

// 替换 Scorer：测试新的评分算法
pipeline.scorer(Box::new(ExperimentalScorer::new()));

可组合架构的优势：

操作 影响范围
新增 Source 零修改现有代码
新增 Filter 只添加一行 .filter(...)
A/B 测试新 Scorer 创建新 Pipeline 变体即可
禁用某个组件 enable() 返回 false

💡 本节小结

设计决策 核心价值
零手工特征 端到端学习，减少数据管道复杂度
Candidate Isolation 分数独立 → 可缓存 → 计算效率
Hash-Based Embeddings 512GB → 3GB，内存可控
多行为预测 改权重 ≠ 改模型，产品迭代快
可组合管道 灵活扩展，A/B 测试友好
